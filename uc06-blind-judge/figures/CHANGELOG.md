# Figure changelog

Why the published figure set changed on 28 July 2026, and what was verified
against the raw logs.

---

## Verified correct — no change to the underlying decision

**The 0.0 samples are a reporting-window artifact.** This was checked, not
assumed. Inside Run 2's 121 s load window there are 48 Indications: 24
carrying a value and 24 empty, in strict alternation with no exception:

```
05:29:31  59043.0      05:29:34  0.0
05:29:37  59043.0      05:29:40  0.0
05:29:43  59043.0      05:29:46  0.0
05:29:48  59043.0      05:29:51  0.0
```

A regular one-in-two pattern sustained across the whole window is the
signature of an empty reporting window, not a metric failure. Omitting them
from the trend line was defensible.

**What changed:** the caption no longer says only "filtered". It now states
the cadence, the exact counts, and why the empty windows are omitted. The
alternation itself is published as its own figure.

## Retired — `04_raw_capture_annotated.png` — REMOVED, NOT REPLACED

The screenshot was taken from **Run 1**, the run voided for a procedural fault
(`mp/run1_ping.txt` visible in the shell, KPM timestamps at `05:20` against
Run 2's `05:29`). A result figure must not come from a voided run.

Its caption also contradicted its own contents: it read *"DRB.UEThpDl =
59,043 — steady, no anomaly"* above a capture showing `0.0`, `59043.0`, `0.0`
in three consecutive samples.

Three replacement figures were drafted and all three were rejected. Everything
a replacement would have carried — the ~2.5 s cadence, the value / 0.0
alternation, the 23-of-24 identical readings — is already stated in the hero
chart's footnote and in METHOD.md §3. A figure that restates what the text
already says costs the reader attention without adding evidence.

The published set is therefore four figures, not five:

```
01_lab_at_work                 the testbed running
02_architecture_dataflow       architecture, data flow, timeline
03_result_hero                 the result: two witnesses, same seconds
05_proof_time_aligned          raw evidence, rendered from the log
```

Numbering is left as-is rather than resequenced, so that references in earlier
posts and commits still resolve.
